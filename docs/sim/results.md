## 方法

- 模拟器在运行时按声明名从 `game.js` **原样抽取** 稀有度表、货柜表、拍卖厅表、蜜月表、物品表和掉落函数（`rollLoot` / `weightedPick` / `tierFee` …），放进 node:vm 沙箱里跑，随机数用带种子的 mulberry32，可复现。默认读 `../../game.js`，`--game <路径>` 指向别的文件。
- 货柜表状态：蜜月后 = `honeymoonEnded=true`；蜜月中 = 第 1 场、现金 ¥1.5 万，不含只触发一次的首开紫/小金保底（节奏模拟里含）；冷手 lossStreak=0；没有稀有柜券、折扣券、广告，5×5 仓库；厅 = 只解锁该厅。比值 = 平均售价 ÷ 实付租金；P/L = 售价 − 租金。表里的比值不含“下一柜 12% 折扣”（节奏里含）。
- 装箱：两种贪心首次适配（① 价值密度降序；② 价值降序），每件试所有旋转，取售价高的方案，装不下的丢弃。**25 格**（最优档）用满 5×5；**20 格**（保守档、稳健档）同样的贪心但最多用 20 格（= 80%×25，“摆得不紧、留空隙”），所以拿不到“利用率 ≥85%”的完美装箱，只能靠零丢弃拿。
- 鉴宝：值 ≥ ¥14,000 的每件货触发，50% 答题 / 50% 跟球，两者都按 70% 成功算。答题答错 = 降一级换物件、货值 ×0.42–0.54；跟球成功 = ×1.05–1.10，失败 = 45% 降一级，否则 ×0.60–0.75。跟球“一般”档没建模。
- 厅对比用同一组种子，厅差值不是抽样噪声。
- 节奏模拟（每档 2,000 局，最多 400 场）：开局 ¥15,000，蜜月按游戏规则（第 1–5 场且现金 < `CASH_END`，一旦结束不再回来；含首开紫/小金保底）。每场先判破产：现金 < min(普通柜实付, ¥5,000) 就结束这一局，**没模拟每日清算重整**。现金 ≥ ¥38,000 时每场按游戏概率（50%，蜜月刚结束 3 场内 68%）刷出限时柜，只在当场有效，不算每日 4 次上限。完美装箱送下一柜 12% 折扣，冷手按游戏规则累计，拍卖厅按峰值现金解锁。没算开箱里程碑、图鉴、每日活动、峰值里程碑奖励（都是小额）。
  - **保守**（判定）：20 格装箱；每场在租得起的柜里选“期望净利最高”的（期望值按当前蜜月状态和厅预先模拟，用折后租金）。
  - **稳健**（判定）：20 格装箱；每场租“折后租金 ≤ 当前现金 40%”的柜里最贵的；如果一个都没有（现金 < 普通柜租金的 2.5 倍），就租租得起的最便宜的柜（通常是普通柜）。限时柜只有刷出来的那场才算。
  - **最优**（参考）：25 格装箱，选柜同保守。
- 中位场数把“没到达”算作无穷大，超过一半没到就记“未达到”；另给“到达的局”的中位。“第 16 场起破产”= 第 16 场以后破产的局 ÷ 全部局。

## 复现

```bash
node docs/sim/tier_ev.js 30000 --json before.json                                 # 现行 main
git worktree add ../econ-retune origin/econ-retune
node docs/sim/tier_ev.js 30000 --game ../econ-retune/game.js --json after.json
node docs/sim/tier_ev.js 30000 --game ../econ-retune/game.js --profile conservative   # 20 格装箱的比值
node docs/sim/tier_ev.js --pace --runs 2000 --game ../econ-retune/game.js            # 节奏：保守 / 稳健 / 最优
```
