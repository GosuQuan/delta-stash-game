## 结论

- 普通柜：比值 1.125（目标 1.08–1.15）✅ 达标；赚钱概率 54.1%（目标 50–60%）✅ 达标
- 精选柜：比值 1.062（目标 1.00–1.08）✅ 达标；赚钱概率 45.3%（目标 40–50%）✅ 达标
- 密封柜：比值 1.069（目标 1.02–1.12）✅ 达标；赚钱概率 36.7%（目标 30–40%）✅ 达标
- 限时豪华柜：比值 1.111（目标 1.05–1.15）✅ 达标；赚钱概率 33.0%（目标 25–35%）✅ 达标
- 最好 10%（P/L P90）随档次拉高：普通柜 ¥3,218 < 精选柜 ¥12,460 < 密封柜 ¥31,514 < 限时豪华柜 ¥106,290 ✅ 达标
- 蜜月期比值 ≥1.10：普通柜 2.70、精选柜 2.15、密封柜 1.16、限时豪华柜 1.16 ✅ 达标
- 拍卖厅比值比无厅高 0～+3 个百分点：✅ 达标（做法：取消全部租金加价，金红权重翡翠 5%→4%、赤金 8%→4%）
- 节奏（按保守档判定）：到 ¥8 万中位 13 场（目标 35–50）❌ 未达标；到 ¥30 万中位 101 场（目标 100–150）✅ 达标，但 37.1% 的局 400 场内没到 30 万（基本都是中途破产），到达的局中位只要 41 场
- 前 15 场破产率 <10%：保守档 3.3% ✅ 达标；最优档 2.3% ✅ 达标
- **没达标的：到 ¥8 万太快**（保守档 13 场、最优档 9 场，目标 35–50）。主要是蜜月给得多：蜜月里普通柜 2.70、精选柜 2.15，玩家一般约 3 场就从 ¥1.5 万冲到约 ¥4.5 万（蜜月结束线）。按指示没动蜜月的普通/精选部分。敏感度：如果开局就没有蜜月（仅作参考），保守档到 8 万中位 49 场，但前 15 场破产率升到 10.3%。要进 35–50 场，需要商业化决定是否收紧蜜月（例如普通/精选蜜月比值压到约 1.3–1.5），或把 ¥8 万目标理解为“到达的玩家”的节奏。
- 另外，全程破产率偏高（最优 27.1% / 保守 37.0%，模拟里破产即结束，没算每日「清算重整」）：原因是“永远租期望净利最高、租得起的柜”会把全部现金押进精选/密封/限时柜，这些柜赚钱概率本来就只有 33–45%。真人会留余量，而且有每日清算重整，实际会低很多。

## 方法

- 模拟器在运行时按声明名从 `game.js` **原样抽取** 稀有度表、货柜表、拍卖厅表、蜜月表、物品表和掉落函数（`rollLoot` / `weightedPick` / `tierFee` …），放进 node:vm 沙箱里跑，随机数用带种子的 mulberry32，结果可复现。默认读 `../../game.js`，`--game <路径>` 可以指向别的文件（本表的“调整后”就是 `--game` 指向 `econ-retune` 分支的 game.js）。
- 状态：蜜月后 = `honeymoonEnded=true`；蜜月中 = 第 1 场、现金 ¥1.5 万，不含只触发一次的首开紫/小金保底；冷手 lossStreak=0；没有稀有柜券、折扣券、广告，5×5 仓库。厅 = 只解锁该厅。
- 装箱：两种贪心首次适配（① 价值密度降序；② 价值降序），每件试所有旋转，每开取售价更高的方案，装不下的货丢弃。**最优档**用完整 25 格；**保守档**同样的贪心，但最多只用 20 格（= 80%×25，模拟“摆得不紧、留空隙”，装箱效率为贪心的 80%）。保守档因此拿不到“利用率 ≥85%”的完美装箱，只能靠零丢弃拿。说明：如果把“八折”理解为货值直接 ×0.8，所有柜子（含普通柜 1.12×0.8≈0.90）都变成负期望，节奏目标无从谈起，所以采用格数口径。
- 结算与游戏 `extract()` 一致：售价 = 已装货值 + 完美装箱奖励（利用率 ≥85% 或零丢弃 → +10%）；比值 = 平均售价 ÷ 实付租金；P/L = 售价 − 租金。表里的比值不含“下一柜 12% 折扣”（节奏模拟里含）。
- 鉴宝：值 ≥ ¥14,000 的每件货触发，50% 答题 / 50% 跟球。答题答对率 70%；跟球也按 70% 成功算（成功 = 命中率 ≥80%，货值 ×1.05–1.10；失败 = <50%，45% 降一级，否则 ×0.60–0.75）。答错 = 降一级换物件、货值 ×0.42–0.54。跟球 50–80% 的“一般”档没建模。
- 厅对比用同一组随机种子（每档固定种子），所以厅差值不是抽样噪声。
- 节奏模拟（每档 2,000 局，最多 400 场）：开局 ¥15,000；每场先判破产（现金 < min(普通柜实付, ¥5,000) → 该局结束，**没模拟每日清算重整**）；现金 ≥ ¥38,000 时每场按游戏概率（50%，蜜月刚结束 3 场内 68%）刷出限时柜，只在当场有效，不算每日 4 次上限；在租得起的柜里选“期望净利最高”的（期望值按该档、当前蜜月状态和当前厅预先模拟），用折后租金算；蜜月按游戏规则（第 1–5 场且现金 < ¥4.5 万，一旦结束不再回来）；完美装箱送下一柜 12% 折扣；冷手按游戏规则累计；拍卖厅按峰值现金解锁，取最高厅。没算开箱里程碑、图鉴、每日活动、峰值里程碑等奖励（都是小额，会让节奏略快）。
- 中位场数把“没到达”算作无穷大，所以超过一半没到就记“未达到”；另给“到达的局”中位数。

## 复现

```bash
node docs/sim/tier_ev.js 30000 --json before.json                             # 现行 main
git worktree add ../econ-retune origin/econ-retune
node docs/sim/tier_ev.js 30000 --game ../econ-retune/game.js --json after.json
node docs/sim/tier_ev.js 30000 --game ../econ-retune/game.js --profile conservative   # 保守档比值
node docs/sim/tier_ev.js --pace --runs 2000 --game ../econ-retune/game.js            # 节奏：两档
node docs/sim/tier_ev.js --pace --runs 1000 --hm-off --game ../econ-retune/game.js   # 敏感度：无蜜月
```

可调参数：`--quiz 0.7`（答题答对率）、`--ball`（跟球成功率，默认等于 --quiz）、`--pity K`（冷手连亏 K 场）、`--cap 400`、`--evn 4000`（节奏里选柜用的期望值样本数）。
