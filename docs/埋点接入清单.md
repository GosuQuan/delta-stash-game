# 埋点接入清单（给 grok 照着接）

> 负责人：游戏用户体验运营设计开发 · 方案与决策见 `docs/埋点方案.md`
> 代码基于 `20260925g` 的 `game.js`，行号会漂移，以函数名为准。
> 接收端代码在 `tools/analytics/`：`worker.js`、`schema.sql`、`wrangler.toml`、`queries.sql`、`client-snippet.js`。

## 第 0 步：基础代码
1. 把 `tools/analytics/client-snippet.js` 整段贴进 `game.js` 的 IIFE，放在 `logMono` 附近。
2. `FEATURES` 加 `ANALYTICS_ENABLED: true`。`ANALYTICS.ENDPOINT` 保持空字符串，事件只进 `window.__analyticsLog`，不发网络请求。
3. `saveGame()` 的 payload 加：`analytics: Object.assign({}, analyticsSave, { playMs: analyticsSave.playMs + (Date.now() - analyticsSessionT0) })`。
4. `loadGame()` 读回：`if (p.analytics && p.analytics.save) analyticsSave = Object.assign(freshAnalyticsSave(), p.analytics);`（老存档没有这个字段，会自动生成新的 `save` id）。
5. `newSaveConfirm()` 在 `clearSave()` 之后：先 `track("new_save", { prev_round: round, prev_peak: peakCash })`（放在重置变量之前），再 `analyticsSave = freshAnalyticsSave()`。
6. 游戏初始化、`loadGame()` 之后首屏可操作时调用一次 `trackSessionStart(!loaded)`。
7. `?mono=1` 调试条会同时显示 `📊` 开头的埋点事件，测试玩家可以直接核对。

## 公共字段（`track()` 自动带，不用手写）
`schema`、`ev`、`ts`、`pid`、`sid`、`save`、`build`、`econ`（`econ-0925h`，只在调数值时改）、`round`、`cash`、`peak`、`hall`、`grid`、`honeymoon`、`eval`、`dev`、`vw`。

### 1. `crate_open`
把扣租金那段的 `usedDisc` 和 `cashBeforeRent` 提到 `if (useFree)` 外面，然后：
```js
const rentPaid = feePaid;
const rentCashPct = !useFree && cashBeforeRent > 0 ? +(rentPaid / cashBeforeRent).toFixed(3) : 0;
if (!useFree) {
  analyticsSave.paidOpens += 1;
  if (rentCashPct <= 0.4) analyticsSave.steadyOpens += 1;
}
const discount = useFree ? "free_token" : usedDisc ? "perfect_pack"
  : (honeymoonActive() && rentPaid < rentBase) ? "honeymoon" : "none";
const rarityCount = {};
loot.forEach((e) => { const d = getDef(e.defId); const r = d ? d.rarity : "unknown"; rarityCount[r] = (rarityCount[r] || 0) + 1; });
roundCtx = {
  tier: tierId, tier_group: tierGroup(tierId), rent_base: rentBase, rent_paid: rentPaid,
  discount, honeymoon_open: honeymoonActive() ? 1 : 0, rent_cash_pct: rentCashPct,
  t0: Date.now(), challenges: 0, challenge_ok: 0, lastNet: null,
};
track("crate_open", {
  tier: tierId, tier_group: roundCtx.tier_group, rent_base: rentBase, rent_paid: rentPaid,
  discount, rent_cash_pct: rentCashPct, items: loot.length, rarity: rarityCount,
  daily_left: dailyLeftFor(tierId), // 限时柜和专属柜的今日剩余次数，其他柜子返回 null
});
```
`dailyLeftFor` 需要新写一个小函数：限时柜用 `ensureLimitedDaily()` 的剩余次数，专属柜用它自己的每日计数，通用柜返回 `null`。

### 2. `round_settle`
```js
analyticsSessionRounds += 1;
const c = roundCtx || {};
track("round_settle", {
  tier: c.tier || null, tier_group: c.tier_group || null, honeymoon_open: c.honeymoon_open || 0,
  discount: c.discount || null, rent_base: c.rent_base || null, rent_cash_pct: c.rent_cash_pct || 0,
  rent_paid: fee, loot_value: lootValue, packed_value: packedValue,
  discard_n: lost, discard_value: lostVal, bonus_n: bonusFromStaging.length,
  util_pct: utilPct, perfect_pack: perfectPack ? 1 : 0, perfect_bonus: perfectBonus,
  empty_refund: emptyCrateRefund, net,
  challenges: c.challenges || 0, challenge_ok: c.challenge_ok || 0,
  dur_s: c.t0 ? Math.round((Date.now() - c.t0) / 1000) : null,
});
if (roundCtx) roundCtx.lastNet = net;
```
注意：免费券开柜 `rent_paid` 为 0，空柜退款时 `empty_refund > 0`，两种情况在查询里都已排除，不参与比值计算。

### 3. `challenge_result`
每个挑战开始时记 `const vBefore = itemValue(entry); const tAsk = Date.now();`，在每个收尾函数里调同一个助手：
```js
function trackChallenge(entry, kind, vBefore, tAsk, ok, protect, hitRate) {
  const vAfter = itemValue(entry);
  if (roundCtx) { roundCtx.challenges += 1; if (ok) roundCtx.challenge_ok += 1; }
  const d = getDef(entry.defId);
  track("challenge_result", {
    kind, rarity: d ? d.rarity : null, ok: ok ? 1 : 0,
    result: vAfter > vBefore ? "up" : vAfter < vBefore ? "down" : "keep",
    value_before: vBefore, value_after: vAfter,
    hit_rate: hitRate == null ? null : +hitRate.toFixed(3),
    protect: protect || "none", answer_ms: Date.now() - tAsk,
  });
}
```
- 答题：`kind` 用 `pickChallengeQuestion()` 返回的 `math` / `logic`；`finish(success)` 里 `ok = success`；`finishProtect(via)` 里 `ok = false`，`protect = via`（`key` / `charge` / `ticket`）。
- 跟随球：`kind = "follow_ball"`；`finishOk` 记 `ok = true`，`acceptFailSettle` 记 `ok = false`，`finishProtect(via)` 记 `ok = false`、`protect = via`；`hitRate` 取 `settleFollowBallHitRate` 用到的命中率。
- 「重试」不算一次结果，只在最终收尾时发一次。

### 4. `peak_reach`
```js
const PEAK_MARKS = [80000, 300000, 1000000];
function notePeakCash() {
  if (cash > peakCash) peakCash = cash;
  for (const m of PEAK_MARKS) {
    if (peakCash >= m && !analyticsSave.peakMarks.includes(m)) {
      analyticsSave.peakMarks.push(m);
      track("peak_reach", { mark: m, rounds_to: round, play_min: playMinutes(), steady_share: steadyShare(), restructure_n: analyticsSave.restructureN });
    }
  }
}
```
`steady_share` 是本档付费开柜里租金 ≤ 现金 40% 的比例，≥ 0.8 的存档算稳健档，只拿它们跟模拟比节奏。

## 帮助页
- 文案：「为了调平数值，游戏会匿名记录开柜、结算等玩法数据，不含姓名、账号、IP 等个人信息，可以随时关闭。」
- 开关「参与匿名统计」，默认打开，切换时调用 `setAnalyticsOptIn(checked)`；关闭后清空待发队列，之后不再记录。

## 验收（接完请自查，测试玩家复核）
1. 带 `?mono=1&eval=1` 开 1 场普通柜并结算，调试条依次出现 `crate_open`、`round_settle`，`window.__analyticsLog` 里两条的 `eval` 都为 `true`，`econ` 为 `econ-0925h`。
2. 用免费券开一场，`round_settle.rent_paid` 为 0，`crate_open.discount` 为 `free_token`。
3. 触发一次守住挑战，出现一条 `challenge_result`，`round_settle.challenges` 为 1。
4. 关掉「参与匿名统计」再开一场，`__analyticsLog` 不再增加。
5. `ENDPOINT` 为空时，Network 面板里没有任何埋点请求。
6. 刷新页面后 `save` 不变；新开档后 `save` 换新，并先出现一条 `new_save`。
7. 自动测试加一条：`track()` 产生的事件里不出现 `name`、`email`、`ip` 等字段。

## 接收端部署（等少权的 Cloudflare 账号）
在 `tools/analytics/` 目录下：
1. `npx wrangler login`（需要少权在浏览器里登录 Cloudflare）
2. `npx wrangler d1 create delta_stash_analytics`，把输出的 `database_id` 填进 `wrangler.toml`
3. `npx wrangler d1 execute delta_stash_analytics --remote --file=schema.sql`
4. `npx wrangler deploy`，得到 `https://delta-stash-analytics.<子域>.workers.dev`
5. 把 `ANALYTICS.ENDPOINT` 改成上面地址加 `/e`，发版
6. 用 `?eval=1` 开几场，跑 `queries.sql` 里的 Q9 确认数据进来了（评测数据被视图排除，要直接查 `events` 表）

接收端已在本地用 SQLite 模拟 D1 测过：合法事件入库、非白名单来源返回 403、超过 64KB 返回 413、非法事件名和格式不对的玩家 ID 被丢弃、表里没有 IP 列，`queries.sql` 的所有查询和每日汇总都能跑通。
